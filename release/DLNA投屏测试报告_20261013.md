## 一、项目背景

绿角犀（GreenRhino）离线媒体播放器需支持 DLNA/UPnP 投屏到智能电视。核心阻塞点：Android 本地媒体存于 `content://` URI，而 DLNA 电视只能拉取 `http(s)://` URL。需要在 Android 端起一个轻量 HTTP Server，把 `content://` 流代理成局域网 HTTP URL，让电视能访问。

### 涉及模块

| 模块 | 文件 | 说明 |
|---|---|---|
| HTTP 代理服务 | `MediaHttpServer.kt` (🆕 236 行) | ServerSocket 手写 HTTP/1.1，零依赖 |
| DLNA 投屏控制器 | `DlnaCaster.kt` (242 行) | SSDP 发现 + SOAP AVTransport 控制 |
| WebView Bridge | `MainActivity.kt` RhinoBridge | 9 个 JS 接口方法，含 castScan/Play/Stop/Pause |
| 前端投屏逻辑 | `src/cast.js` | Android 宿主检测 + castPlay 调用 |
| 权限声明 | `AndroidManifest.xml` | 4 条投屏必需权限 |

## 四、MediaHttpServer 实现要点

### 4.1 为什么不用 `com.sun.net.httpserver.HttpServer`？

| 方案 | 问题 |
|---|---|
| ~~`com.sun.net.httpserver.HttpServer`~~ | ❌ **Java SE API**，Android 从未实现，编译报 `Unresolved reference: sun` |
| ~~OkHttp/Retrofit~~ | ❌ 引第三方依赖，违反项目零依赖原则 |
| ✅ **纯 `java.net.ServerSocket`** | ✅ Android 原生，手写 HTTP/1.1，236 行，完全可控 |

### 4.2 路由设计

```
GET /stream/{base64_url_safe(content://...)}
  → base64 decode (URL_SAFE: +→-, /→_, 去=)
  → Uri.parse(content://media/...)
  → contentResolver.openInputStream()
  → 64KB chunk 流式输出
```

### 4.3 关键实现

```kotlin
// 绑定 0.0.0.0，端口由 OS 分配（避免冲突）
ServerSocket().apply {
    bind(InetSocketAddress("0.0.0.0", 0), 4)
}

// 局域网 IP（WifiManager）
private fun getLanIp(): String {
    val wifi = context.applicationContext.getSystemService(WIFI_SERVICE::class.java)
    val ip = wifi.connectionInfo.ipAddress  // int → little-endian dotted decimal
    return "${ip and 0xFF}.${ip shr 8 and 0xFF}.${ip shr 16 and 0xFF}.${ip shr 24 and 0xFF}"
}

// Range 支持（DLNA TV Seek 会发 Range: bytes=0-）
if (rangeStart != null) {
    responseCode = 206
    responseBodyLen = contentLen - rangeStart
    // InputStream.skip(rangeStart) 后开始读
} else {
    responseCode = 200
    responseBodyLen = contentLen
}
```

### 4.4 自动检测 media type + content length

```kotlin
val contentType = cr.getType(contentUri) ?: "application/octet-stream"
val contentLen = cr.query(contentUri, arrayOf(OpenableColumns.SIZE))?.use {
    if (it.moveToFirst()) it.getLong(0) else -1
} ?: -1
```

## 六、踩坑清单（4 条，全部已修复）

### ISS-20261012-008：`com.sun.net.httpserver` 在 Android 上不存在 🔥 P0 ✅

| 项 | 详情 |
|---|---|
| 归类 | `#android-api #api-mismatch` |
| 现象 | MediaHttpServer.kt 用 `HttpServer.create()` 编译报 `Unresolved reference: sun` |
| 根因 | **Java SE API**，JDK 6+ 有，Android 从未实现。Android 只有 `java.net.ServerSocket`、`HttpURLConnection` |
| 修复 | 全部重写为纯 ServerSocket + 手写 HTTP/1.1 解析（236 行） |
| 预防规则 | **Android 上凡是 `com.sun.*` 开头的 Java SE API 一律不存在！不确定就先查 Android Developers 文档** |
| Commit | `519a7ee` |

### ISS-20261012-009：Android 13+ 动态注册 Receiver 崩溃 P1 ✅

| 项 | 详情 |
|---|---|
| 归类 | `#android-13 #receiver #security` |
| 现象 | `registerReceiver(receiver, filter)` 崩溃 `SecurityException: One of RECEIVER_EXPORTED or RECEIVER_NOT_EXPORTED should be specified` |
| 根因 | Android 13 (API 33) 起加强安全，动态注册必须显式声明导出性 |
| 修复 | `if (Build.VERSION.SDK_INT >= TIRAMISU) registerReceiver(..., RECEIVER_NOT_EXPORTED) else registerReceiver(...)` |
| 预防规则 | **Android 13+ 所有 `registerReceiver()` 必须加版本 guard + flag 参数；Manifest 静态注册不受影响** |
| Commit | `bb16d41` |

### ISS-20261012-010：Moto 量产版 Log.d/Log.i 全被过滤 P2 ✅

| 项 | 详情 |
|---|---|
| 归类 | `#android-logcat #moto #manufacturer` |
| 现象 | `Log.d("GreenRhino", "...")` 在 logcat 里完全看不到，只有系统 tag 可见 |
| 根因 | Moto XT2401 量产版加了 App 日志过滤策略，非系统 tag 的 Debug/Info 级被静默丢弃 |
| 修复 | 改用 **BroadcastReceiver 触发 + netstat + curl 网络验证**——绕开日志层直接验证功能 |
| 预防规则 | **Moto/小米/华为等量产版上调试 App，优先用 BroadcastReceiver / ContentObserver / LocalSocket 绕过 logcat** |
| Commit | `bb16d41` |

### ISS-20261012-011：Android SSDP 多播必须持 MulticastLock 🔥 P1 ✅

| 项 | 详情 |
|---|---|
| 归类 | `#android-multicast #ssdp #dlna` |
| 现象 | DlnaCaster.discover() 发了 SSDP M-SEARCH 但永远收不到电视回复 |
| 根因 | Android 默认省电策略**丢弃所有 WiFi 多播包**，除非持 `WifiManager.MulticastLock`。UDP send 不需要锁（发出去了），但回复包被系统静默丢弃 |
| 修复 | `wifi.createMulticastLock("GreenRhino-DLNA").apply { setReferenceCounted(false); acquire() }` 在 SSDP 扫描前获取，try/finally 释放 |
| 预防规则 | **Android 上任何 UDP 多播（SSDP/mDNS/Chromecast discovery）必须先拿 MulticastLock，否则发了等于白发**。Manifest 必须有 `CHANGE_WIFI_MULTICAST_STATE` 权限 |
| Commit | `6c01ff9` |

│                   前端 cast.js / RhinoBridge                    │

                               │
                               ▼

│           └── NO  → 直接用原 URI                                │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│ MediaHttpServer (ServerSocket 0.0.0.0:OS_RANDOM_PORT)          │
│  ① base64 URL_SAFE decode → Uri.parse(content://...)           │

┌─────────────────────────────────────────────────────────────────┐
│                    DLNA 智能电视                                │
